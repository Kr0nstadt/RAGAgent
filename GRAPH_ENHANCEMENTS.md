# Расширение Graph RAG для моделирования 1С:ERP

Решение работает с графом и Python-кодом локально. Обращения к Wormsoft,
DeepSeek и Ollama по умолчанию запрещены. Они возможны только после явного
`--allow-llm` или `RAG_ENABLE_LLM=1`.

## Что добавлено

- Типизированный L3: реквизиты, табличные части, типы ссылок,
  `FillChecking`, `CreateOnInput`, документы-основания, регистры-регистраторы,
  подсистемы, команды и пути интерфейса.
- Обратный план зависимостей НСИ: от создаваемого объекта к справочникам и
  перечислениям, которые могут понадобиться раньше или при заполнении.
- Цепочки документов по `BasedOn` и по обязательным документным ссылкам.
  Для каждого шага выводятся возможные регистры и найденные пути интерфейса.
- Отдельный Task Graph для каждого входного ТЗ. Он не загрязняет статический
  ERP-граф и хранит блоки, входы, действия, результаты, контроли, ограничения,
  исключения и порядок передачи результатов.
- Безопасная потоковая загрузка DOCX, TXT, MD, XLSX и PDF до 250 МБ по
  умолчанию. DOCX/XLSX разбираются локально; проверяются расширение, размер и
  риск zip-bomb.
- 35 типов L2-уточнений в статическом графе и адаптивный каталог вопросов по
  ТЗ. Вопросы выдаются раундами, а не фиксированным списком из пяти пунктов.
- Контракт `TzNormalizer` для будущего PI/herdr-субагента. Возвращённые им ERP
  ID проходят проверку по статическому графу; сетевой клиент намеренно не
  встроен.
- Разреженный CSR TF-IDF вместо плотной матрицы: поиск больше не пытается
  выделить около 1,8 ГБ на вычисление cosine similarity.

## Основной локальный процесс

```powershell
# Один раз разобрать файл ТЗ в Task Graph
python graph_rag_1c_erp.py ingest-tz "C:\path\task.docx" --task-id my-task

# Получить первый раунд из 10 вопросов; --all показывает весь текущий пул
python graph_rag_1c_erp.py task-questions my-task --limit 10

# Сохранить ответ. Для вопроса сопоставления можно передать точный ERP node ID
python graph_rag_1c_erp.py answer-task my-task "question:..." "ERPcode/Documents/ЗаказКлиента"

# Следующий раунд не повторяет отвеченные вопросы
python graph_rag_1c_erp.py task-questions my-task --limit 10

# Построить проверяемый процессный план и черновик инструкции без LLM
python graph_rag_1c_erp.py plan-task my-task --dependency-depth 3
```

Результаты находятся в `task_data/<task-id>/`:

- `task_graph.json` — исходная структурированная модель ТЗ;
- `answers.json` — ответы пользователя;
- `erp_mapping.json` — подтверждённые связи и кандидаты;
- `process_plan.json` — НСИ, документы, цепочки, регистры и пробелы;
- `instruction_draft.md` — офлайн-черновик. Пока есть блокирующие вопросы или
  разрывы цепи, он явно помечается как черновик.

## Команды статического графа

```powershell
# Полная сборка из ИТС + ERPcode
python graph_rag_1c_erp.py build

# Инкрементально добавить типизированные L3/UI-связи в старый индекс
python graph_rag_1c_erp.py enhance

# Обновить только L2-вопросы и связи со сценариями
python graph_rag_1c_erp.py refresh-clarifications

# Мигрировать старый плотный TF-IDF в CSR
python graph_rag_1c_erp.py compact-index

# Обратная цепочка подготовки НСИ
python graph_rag_1c_erp.py dependencies "Номенклатура" --max-depth 3

# Подтверждённая цепочка документов
python graph_rag_1c_erp.py document-chain "Заказ клиента" "Реализация товаров и услуг"

# Быстрый поиск без LLM
python query_graph.py "создать номенклатуру"

# Проверка целостности
python graph_rag_1c_erp.py validate
```

`FillChecking=ShowError` отмечается как «обязательно по метаданным», но не как
безусловное бизнес-правило: применимость может зависеть от операции,
функциональных опций и формы. `CreateOnInput=Auto/Use` означает кандидата на
создание из поля, а не гарантию наличия кнопки и прав. Связь документа с
регистром означает, что документ может быть регистратором; конкретные движения
всё равно зависят от операции, статуса и данных документа.

## HTTP-загрузка большого ТЗ

Сервер принимает raw binary body и пишет его потоково:

```powershell
python graph_rag_1c_erp.py serve --port 8000
curl.exe --data-binary "@C:\path\task.docx" `
  "http://127.0.0.1:8000/tasks/upload?filename=task.docx&max_file_mb=250"
```

Дальше доступны:

- `GET /tasks/<id>/questions?limit=10`;
- `POST /tasks/<id>/answers` с JSON-словарём `question_id: answer`;
- `GET /tasks/<id>/plan`;
- `GET /tasks/<id>/model`.

Эндпоинт `/instruct` возвращает 403, пока LLM не разрешена явно.
