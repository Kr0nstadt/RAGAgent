# Интеграция с мобильным приложением 1С:Заказы

Мобильное приложение 1С:Заказы ([https://mobile-orders.1c.ru/](https://mobile-orders.1c.ru/)) предназначено для менеджеров по продажам или торговых представителей, которым необходимо принимать заказы от клиентов мобильно, вне офиса. Оно предназначено для работы на мобильных устройствах под управлением операционных систем iOS и Android.

Приложение позволяет:

■ Хранить информацию о товарах, их остатках, ценах продажи и закупки;

■ Хранить базу клиентов и их контактную информацию;

■ Формировать заказы с учетом актуальных остатков и цен;

■ Производить отгрузку и оплату заказов;

■ Производить базовые складские и денежные операции;

■ Вести работу в режиме совместного использования с настольным или облачным решением 1С:Управление торговлей и 1С:ERP Управление предприятием.

Для синхронизации необходимо средствами конфигуратора опубликовать web – сервис «CustomerOrdersExchange.1cws».

После публикации, web-сервис должен быть доступен в браузере по адресу: http(s)://ваш\_сервер/ваш\_каталог\_публикации/ws/CustomerOrdersExchange?wsdl

Мобильное приложение доступно пользователям, которые входит в группы с типовыми профилями доступа:

■ - торговый представитель;

■ - менеджер продаж;

■ - супервайзер торговых представителей.

Также мобильное приложение будет доступно в нетиповых профилях, включающих роль Использование мобильного приложения "1С: Заказы клиентов".

Интеграция с 1С:Заказы настраивается в разделе НСИ и администрирование – Настройка интеграции – Интеграция с 1С:Заказы.

Для использования интеграции требуется включить опцию Разрешить синхронизацию данных с мобильным приложением "1С:Заказы". Дополнительно можно настроить синхронизацию реквизитов объектов и отправку push-уведомлений. Также из формы настроек доступен список подключенных мобильных устройств и ссылка с актуальной инструкцией по подключению.

При первом запуске приложения на мобильном устройстве нужно выбрать режим работы:

■ Режим синхронизации с 1С — в этом режиме  потребуется указать информацию для подключения:

○ Адрес сервиса обмена, по которому была опубликована базы (см. выше);

○ Пользователь — имя пользователя, используемого для работы с информационной базой;

○ Пароль пользователя информационной базой.

■ Автономный режим — в этом режиме работа приложения не поддерживает синхронизацию данных с информационной базой, приложение является полностью автономным.

После этого приложение готово к работе.

Рекомендуется выполнять первую синхронизацию на высокоскоростном беспроводном подключении wi-fi, поскольку, в зависимости от настроенных фильтров, она может занять продолжительное время. Также рекомендуется устанавливать фильтры в настройках пользователя с учетом реальной работы пользователя. Стоит ограничивать передаваемые данные обмена для оптимизации скорости выполнения обмена, а также для ограничения объема трафика.

При синхронизации данных следует учитывать следующие особенности:

■ Выгружаются клиенты с доступными договорами продажи.

■ Если используются сегменты партнеров, то требуется создать сегмент клиентов со всеми клиентами. Отбор не работает по динамическим сегментам (ограничение).

■ Способ формирования сегмента – Периодически обновлять. Поставить флаг Проверять на вхождение при создании нового клиента.

■ Номенклатура выгружается, если есть установленные цены, подходящими для выгрузки. Это зависит от настроек использования соглашений с клиентами.

○ При использовании типовых и индивидуальные соглашениях считается, что общие ценовые условия задаются в типовых соглашения (в индивидуальных – исключения) и в мобильное приложение выгружаются цены по видам цен из типовых соглашений.

○ Если используются только индивидуальные соглашения, то цены выгружаются из индивидуальных соглашений.

○ Если соглашения не используются, то выгружаются все доступные виды цен, используемые для продажи.

■ Используемые соглашения, обязательно должны быть действующие с установленными сроками.

Чтобы получить товары и цены войдите в Главное меню - Виды цен. Выполните команду Обновить. По этой команде выгружаются все товары и цены вне зависимости от регистрации в управляющей информационной базе.

Для отображения списка товаров в мобильном приложении нужно перед тем как нажать команду Принять заказ выбрать конкретного клиента (на месте где написано Данные по всем клиентам, тогда после нажатия команды Принять заказ на следующем шаге появится список товаров.

Если в базе используются только типовые соглашения об условиях продаж, тогда прайс-лист берется из типового соглашения. В таком случае нужно нажать Принять заказ, выбрать прайс-лист, выбрать товары и далее уже выбрать клиента.

В случае возникновения проблем обмене данными следует также проверить следующее:

1\.          Проверить справочник валют на предмет наличия дублирования валюты RUB/руб.

2\. Убрать битые ссылки в регистре сведений Соответствие условий продаж мобильного приложения "1С: Заказы клиентов"

3\. Перезаписать "проблемных" контрагентов
