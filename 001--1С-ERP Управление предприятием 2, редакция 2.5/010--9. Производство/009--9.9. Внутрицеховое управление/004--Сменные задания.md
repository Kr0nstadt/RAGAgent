# Внутрицеховое управление

После формирования партий этапы производства передаются к выполнению и становятся основанием для организации работ в цехах. Исполнение этапов в подразделении делегируется локальному диспетчеру. Исполнение этапов может являться конечной точкой управления выполнением, а может уточняться при помощи производственных операций для более детального управления и делегирования работ исполнителям операций.

## РМ Выполнение этапов

Рабочее место предназначено для управления выполнением этапов в цеху. В это РМ попадают этапы начиная со статуса К выполнению и выше.  Этапы в статусах Формируется и Сформирован не попадут сюда ни при каких отборах. С точки зрения управления процессом, это основное РМ, в котором локальный диспетчер получает от главного диспетчера пул работ к исполнению.

В шапке формы расположены отборы:

Подразделение – для выбора цеха, чьи этапы должно отображаться.

Обеспечение – отбор по обеспеченности.

Период – позволяет отобрать этапы по периоду исполнения в соответствии с графиком производства.

Состояние – отбор этапов по состояниям выполнения, которые определяются из статусов этапов и их предшественников. Возможные состояния для отбора: Ожидание предшествующих, Начаты предшествующие, Можно выполнять, Начат, Завершен.

Состояние определяется статусом самого этапа и статусом этапа-предшественника той же партии, к которой относится этап. Состояние **Ожидание предшествующих** означает, что у этапа есть предыдущий этап, который еще не начали выполнять:

**Начаты предшествующие** означает, что у этапа есть предыдущий этап, который уже начали выполнять:

Отборы по предшественникам позволяют управлять видимостью этапов к выполнению в зависимости от того, как скоро (логически) может дойти их очередь, даже если отсутствует график производства либо этапы выполняются с отклонением от графика.

Состояние **Можно выполнять** получает этап, у которого нет незавершенных предшественников. То есть все предшествующие этапы завершены либо сам этап является первым этапом.

Расчет состояния этапов по предшественникам отличается при использовании статической и динамической структуры заказа. При статической структуре предшественниками считаются не только этапы своей партии (той же спецификации), но и этапы, относящиеся к полуфабрикатам, производимым в процессе.

При использовании динамической структуры анализируются только этапы-предшественники своей партии. То есть в любой запущенной партии первый этап всегда можно выполнять, даже если входящие в него полуфабрикаты еще не произведены. Такое отличие в поведении объясняется тем, что в динамической структуре при распределении запасов любой потребляемый полуфабрикат для запущенной партии ничем не отличается от обычного материала. Мало того, даже если полуфабрикат изначально планировалось произвести, может оказаться, что производить его не надо будет, потому что, например образуется свободный остаток или ожидаемое поступление. Поэтому готовность входящего полуфабриката  отслеживается через обеспеченность, как и для  материалов. РМ формирования партий запуска позволяет контролировать обеспеченность запускаемых партий, включая обеспеченность полуфабрикатами. Если принято решение запустить (сформировать)  партию, не взирая на необеспеченность, значит её первый этап безусловно можно выполнять.

Состояния **Начат** и **Завершен** соответствуют статусам этапа, безотносительно предшественников.

Из рабочего места можно открыть отметить начало  или завершение выполнения выбранных этапов производства, можно открыть этап. Есть возможность перейти к РМ Выполнение операций с предустановленным отбором по выбранному этапу.

В списке этапов есть колонка Начало следующего этапа, которая показывает плановую дату начала выполнения этапа, которому выбранный этап является предшественников. Эта колонка может использоваться для принятия решения о том, какой этап брать в работу в первую очередь.

## Производственные операции

Механизм управления исполнением производственных процессов в цехе предназначен для диспетчирования технологических операций в «ручном» режиме и позволяет:

■ сформировать список требующихся для исполнения этапа операций;

■ распределить операции на рабочие центры;

■ назначить исполнителя и принять операцию к исполнению;

■ оформить выполнение операций с указанием израсходованных материалов и произведенных трудозатрат.

Возможность диспетчирования операций настраивается для каждого подразделения индивидуально и определяется реквизитом Использовать пооперационное управление этапами производства на закладке Производство по заказам в параметрах производственного подразделения из списка Структура предприятия.

  

Отдельными реквизитами в настройках подразделения задается характер использования операций для сбора фактических данных по исполнению этапов производства:

■ установка флажка Материалы в операциях позволяет регистрировать использование материалов в разрезе операций;

■ установка флажка Выходные изделия в операциях дает возможность отразить выпуск в привязке к операциям.

### Документ Производственная операция

Документ предназначен для управления выполнением операций этапа производства. Описывает выполнение одной операции технологического маршрута на заданное количество. Формируется для этапов в состоянии "Начат" из рабочего места Выполнение операций из пула запланированных к выполнению операций, если в производственном подразделении не включено использование сменных заданий. При использовании сменных заданий операции формируются в рабочем месте формирование сменных заданий путем назначения операции на смену.

Состав операций, подлежащих выполнению в рамках этапа, по умолчанию определяется выбранной ресурсной спецификацией.

Объем исполнения операций задается во временных и количественных показателях. Например, операция приготовления раствора нормируется из расчета 50 кг (объем исполнения в количественных показателях) за 1 час (временной показатель).

Жизненный цикл производственной операции описывается статусами:

● **Создана** - операция создана, но пока еще не принята в работу.

● **Выполняется** - назначен исполнитель, операция принята в работу.

● **Выполнена** - успешно завершено выполнение операции (в полном объеме либо частично). Указанные в операции материалы, трудозатраты и выходные изделия будут перенесены в фактическое выполнение этапа производства.

● **Не выполнена** - выполнение операции не начиналось. Количество операции возвращается в пул требующих выполнения.

● **Пропущена** - операция не выполнена и не будет выполняться в дальнейшем. Статус доступен если в операции маршрутной карты включен флажок Можно пропустить выполнение.

Форма документа содержит закладки:

Основное - основные реквизиты операции.

Материалы и работы - Расход материалов и работ при выполнении операции. При формировании операции заполняется из маршрутной карты. Может быть заполнена вручную либо подбором из этапа производства. Закладка доступна, если в настройках производственного подразделения включен флажок Материалы в операциях. Если материал из операции отсутствует или отменен в этапе производства, строка выделяется шрифтом другого цвета и угловыми скобками. Таким образом система предупреждает, что согласно технологии материал нужен, но он не был обеспечен. На уровне операции нужно принять решение - выбрать другой материал или удалить строчку, иначе операция не проведется.

Выходные изделия - фактическое получение выходных изделий в результате выполнения операции. Закладка доступна, если настройках производственного подразделения включен флажок Выходные изделия в операциях

Трудозатраты - фактические трудозатраты при выполнении операции

Информация о материалах и выходных изделиях переносится в этап производства после завершения операции. Фактическая информация о трудозатратах из операции в этап не переносится. Движения в учете по фактическим трудозатратам делаются самим документом операции.

Поддерживается следующий регламент работы с документами Производственная операция:

#### Шаг 1

Сотрудники производственно-диспетчерского отдела (ПДО), являющиеся пользователями системы в ранге главного диспетчера, передают этапы к выполнению. Этапы появляются в рабочем месте Производство – Внутрицеховое управление – Выполнение этапов.

#### Шаг 2

Диспетчер в цехе (пользователь с правами локального диспетчера) принимает этап к выполнению, переводя его в статус Начат.

При этом для этапа на основании выбранной ресурсной спецификации (или маршрутной карты, если переход к использованию операций в спецификациях не выполнен) создается перечень подлежащих выполнению документов Производственная операция.

■ В процессе выполнения производственная операция меняет статус с Создана на Выполняется, Выполнена или Не выполнена.

■ Статус Не выполнена трактуется как «не начиналась». Данные операции не загружаются в этап производства.

■ Для отражения частичного выполнения операции реквизит Количество в документе разделяется на план и факт.

■ Статус Пропущена доступен если в операции МК взведен флаг Можно пропустить выполнение. От статуса Не выполнена отличается тем, что пропущенные операции недоступны для повторного назначения и выполнения.

■ Реквизит Требует повторения доступен в статусе Выполнена, если в операции МК взведен флаг Можно повторить выполнение. Дает возможность многократного повторения операции.

Операции появляются в рабочем месте Производство – Внутрицеховое управление – Выполнение операций. В табличной части на закладке Выполнение операций в рабочем месте Выполнение операций отражаются актуальные операции в разных статусах выполнения.

Отбор операций в рабочем месте Выполнение операций с фильтром по рабочему центру покажет все операции, запланированные к выполнению на данном РЦ, а также операции, где выбран вид рабочих центров, в который входит указанный в отборе РЦ, но конкретный РЦ для исполнения еще не указан. Это позволяет контролировать весь объем подлежащих диспетчированию операций по конкретному виду оборудования.

Поддерживается корректировка состава операций в процессе исполнения - Производственная операция может быть создана вручную. Операцию можно разбить:

#### Шаг 3

Для операций определяется исполнитель, и они отдаются для выполнения – форма Принять в работу операцию. Исполнителем может быть конкретный рабочий (выбор из списка Физические лица) или бригада (выбор из списка Бригады).

Операция может выполняться несколькими исполнителями. Для каждого из них создается отдельный документ принятия операции в работу. Для каждого отдельного исполнителя принятой в работу операции предусматривается свое подготовительно-заключительное время.

#### Шаг 4

При необходимости исполнители заполняют в документах Производственная операция сведения об использованных в ходе выполнения операции материалах (закладка Материалы и работы) и объемах трудозатрат (закладка Трудозатраты).

#### Шаг 5

Исполнители отмечают выполнение операций. При этом фактические данные из документов Производственная операция попадают в документы Этап производства.

Детализация выработки сотрудников до конкретных производственных операций включается  функциональной опцией НСИ и администрирование - Производство – Операции - Оформлять выработку сотрудников на основании производственных операций. Для этапов с пооперационным управлением распоряжением на оформление выработки является документ Производственная операция. В документе Этап производства в этом случае отключается учет фактических данных трудозатрат и контроль их выполнения, остаются только плановые данные

#### Шаг 6

После выполнения операций этапа диспетчер цеха отмечает завершение выполнения этапа производства. Контроль выполнения все производственных операций на момент завершения этапа включается опцией НСИ и администрирование - Производство – Операции – Контроль выполнения операций при закрытии этапов производства.

Для отслеживания выполнения операций по этапу можно использовать контекстный отчет Ход выполнения производственных операций, который формируется для этапов производства.

## РМ Выполнение операций

Рабочее место предназначено для управления выполнением производственных операций.

Внешнее представление формы зависит от настроек производственного подразделения. Если в подразделении не включено использование сменных заданий, на форме представлены 3 закладки: Выполнение операций, Операции, Контроль выполнения операций. При использовании сменных заданий остаются только закладки Операции и Контроль выполнения операций.

## Сменные задания

Документ «Сменное задание» предназначен для фиксации перечня заданий на рабочую смену и последующего отажения их выполнения при закрытии смены. Задания – это документы «Производственная операция».

Использование сменных заданий не является обязательным. При достаточной цифровизации для управления производством внутри цеха предпочтительно использовать рабочее место "Выполнение операций" без использования сменных заданий. Это позволяет более гибко реагировать на изменения в производственной программе. Сменные задания больше подходят для управления цехом в ”бумажном стиле”, порциями в ритме смен, при котором план работ фиксируется на начало смены, а в конце смены отражаются результаты выполнения работ. При этом изменения в задании по ходу смены незначительны и скорее являются исключением, отклонением, нежели правилом.

Если по ходу смены регулярно происходят значительные изменения в задании, то следует рассмотреть отказ от использования сменных заданий в пользу более оперативного управления через РМ "Выполнение операций".

Использование сменных заданий определяется индивидуально для производственных подразделений.  Для включения сменных заданий в параметрах подразделения устанавливаются настройки:

■ Работа в несколько смен – устанавливается если работа в подразделении ведется в две и более рабочие смены. В этом случае необходимо определить состав смен подразделения. Для определения состава смен и их расписания используется справочник «Графики работы».

■ Использовать сменные задания - устанавливается если требуется объединять производственные операции в сменно-суточные задания, назначаемые на конкретный интервал рабочего времени.

Индивидуальные операции создаются для конкретного документа этапа производства. Не имеют связи с НСИ и описываются непосредственно документами Производственная операция. ## Пооперационное планирование

Для новых ИБ недоступно включение этой функциональности. Подсистема предоставляется как есть и не рекомендуется к использованию на новых проектах.

■ «Функциональность MES в 1С:ERP - диспетчеризация, корректировка планов на основе данных факта, работа с браком» -[https://its.1c.ru/video/erp\_automation\_mes\_dispatch](/video/erp_automation_mes_dispatch).

### Назначение

Пооперационное планирование предназначено для формирования точного расписания выполнения производственных операций с указанием времени выполнения и конкретных рабочих центров. При формировании расписания учитывается доступность рабочих центров, их производительность и условная стоимость работы, необходимость переналадок, параметры моделей и сценариев планирования.

### Особенности и ограничения

Важно понимать, что пооперационное планирование предъявляет высокие требования как к детальности и качеству производственной НСИ, так и к уровню организации производства в целом на предприятии. Но при этом система позволяет на внедрении отложить включение пооперационного планирования на более поздний срок, и делать это не на все производство сразу, а для выбранных подразделений. То есть можно сначала запустить управление производством без использования операций, потом включить пооперационное управление (без планирования), и только потом, если в этом будет необходимость, включить пооперационное планирование для тех подразделений, которые к этому готовы. Именно в такой последовательности рекомендуется подходить к задаче пооперационного планирования, а **не пытаться начинать внедрение сразу с пооперационного планирования**.

Пооперационное планирование не проверяет последовательность выполнения этапов, работает в рамках, заданных графиком производства. Результат пооперационного планирования никак не влияет на график производства. Если пооперационное расписание выйдет за рамки, заданные графиком производства, это нужно отрабатывать вручную. Например, откорректировав даты выполнения этапов или изменив спецификации для построения более адекватного графика производства. Желательно избегать таких ситуаций, когда график производства оказывается невыполнимым по данным пооперационного планирования. Например, по графику производства получается, что заданный объем работ может быть выполнен за день, а пооперационное планирование не может разместить выполнение всех операций в один день. Это некорректно описанная НСИ.

При использовании пооперационного планирования недоступна функциональность сменных заданий.

Не рекомендуется использовать пооперационное планирование, если полученное расписание не будут стремиться реально исполнять на производстве. 

Пооперационное планирование осуществляется на основании переданных к выполнению производственных этапов.

Пооперационное планирование недоступно при использовании динамической структуры заказа на производство.

На текущий момент подсистема пооперационного планирования не развивается и не рекомендуется к использованию на новых проектах.

### Настройка и использование

Доступность планирования (составления пооперационного расписания) для производственных подразделений (элементов списка Структура предприятия) определяется отдельным параметром Использовать пооперационное планирование на закладке Производство по заказам.

Пооперационное расписание для конкретного подразделения осуществляется в рабочем месте Производство – Внутрицеховое управление – Пооперационное планирование. Перед пооперационным планированием уточняются следующие параметры:

■ Момент планирования – начало отсчета размещения производственных операций;

■ Горизонт планирования – интервал размещения производственных операций (начиная с момента планирования);

■ Нормативное время на регистрацию выполнения – максимальное время регистрации начала производственной операции (например, если операция запланирована на 8.00 и нормативное время установлено равным 1 часу, то в случае отсутствия в 9.00 информации о начале запуска операции она подлежит перепланированию);

■ Подразделение – цех, участок, для которого планируется расписание;

■ Модель планирования – модели и сценарии планирования, на основании которых формируется пооперационное расписание.

Для каждого рабочего центра определяется коэффициент времени работ, а также расценки работ и переналадки, которые учитываются при расчете стоимости выполнения операции данным РЦ по формуле: Стоимость = Норма времени \* Коэффициент \* Расценка.

В модели планирования дополнительно могут быть использованы сценарии планирования, позволяющие осуществлять настройки:

■ Изменение парка оборудования:

○ увеличение парка оборудования – для вида РЦ можно добавить необходимое количество дополнительного оборудования с указанием аналога;

○ уменьшение парка оборудования – указываются конкретные РЦ, исключенные из планирования (например, в связи с ремонтом).

■ Изменение графика работы:

○ для подразделения – график работы будет изменен для всех РЦ данного подразделения;

○ для вида рабочих центров – график работы будет изменен для всех РЦ данного вида;

○ для конкретного рабочего центра – график работы будет изменен только для указанного РЦ.

Диспетчирование и контроль выполнения операций при пооперационном планировании осуществляются в отдельном рабочем месте Производство – Внутрицеховое управление – Выполнение операций (МЕS). Данное рабочее место позволяет осуществлять гибкое управление операциями (например, формировать их заблаговременно в привязке к исполнителям и рабочим центрам – кнопка Создать), а также контролировать их фактическое выполнение. А именно:

■ по кнопке Принять в работу для операции создается документ Производственная операция со статусом Выполняется и определяется исполнитель;

■ по кнопке Отметить выполнение для операции создается документ Производственная операция со статусом Выполнен и определяется исполнитель.

По итогам выполнения производственной операции отражаются выпущенная продукция, фактический расход материалов и трудозатрат, после чего производится автоматическая загрузка полученных данных в этап производства.
