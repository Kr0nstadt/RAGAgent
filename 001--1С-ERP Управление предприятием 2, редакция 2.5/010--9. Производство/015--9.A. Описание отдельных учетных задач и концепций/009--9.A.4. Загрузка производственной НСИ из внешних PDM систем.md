# Загрузка производственной НСИ из внешних PDM систем

## Для чего предназначено

Зачастую на производственных предприятиях нормативно-справочная инфомация (НСИ) ведется во внешних системах (PDM, PLM и т.п.). Для исключения повторного ввода информации в 1С:ERP и для обеспечения ее корректного вида в системе предусмотрен механизм загрузки НСИ из внешних систем.

## Загружаемые и сопоставляемые данные

На стороне 1C:ERP все данные, поиск и обработка которых производится при загрузке, делятся на две группы:

\- **Загружаемые данные** – в группу входят номенклатура и характеристика, виды рабочих центров и рабочие центры, ресурсные спецификации, этапы, операции, виды работ. Элементы соответствующих справочников могут автоматически создаваться при загрузке.

\- **Сопоставляемые данные** – в группу входят подразделения (цеха), участки, виды номенклатуры, схемы обеспечения, а также любые другие ссылочные типы данных, не относящиеся к загружаемым. Элементы этих справочников автоматически не создаются. В файлах данных они представлены только в виде ключевого поля, необходимого для поиска и сопоставления по регистрам соответствия объектов.

## Данные, загружаемые из PDM

Предусмотрена загрузка следующих сущностей:

\- Изделия и материалы

\- Составы изделий

\- Производственное оборудование

\- Аналоги (разрешения на замену)

\- Технология производства

\- Трудовое нормирование

## Общий порядок работы

1\. Система-отправитель формирует набор файлов в одном из поддерживаемых форматов – XML, JSON;

2\. На стороне 1C:ERP файлы читаются специальной обработкой, в регламентном задании по расписанию;

3\. Проверяется полнота заполнения обязательных полей, отсутствие ошибок в связях между загружаемыми сущностями и прочих возможных проблем;

4\. Обнаруженные проблемы фиксируются в протоколе и подлежат рассмотрению пользователем;

5\. Данные загружаются в объекты системы 1С:ERP

## Источники данных

Загрузка выполняется в разрезе Источников данных. Если данные загружаются из нескольких внешних систем, необходимо для каждой создать и настроить Источник данных. Источник содержит Правила загрузки данных и другие параметры.

Список источников доступен через команду НСИ и администрирование – Настройка интеграции – Загрузка производственной НСИ – Настройка источников данных и правил загрузки.

### Настройка правил загрузки

На закладке Настройка правил загрузки для выбранных слева типов данных справа отображается таблица, в которой для требуемых реквизитов описываются способы получения значений. Доступны такие способы, как Не использовать, Взять из файла, Установить в значение, Рассчитать по алгоритму, Найти по коду, Найти по наименованию.

#### Не использовать

Такой способ может быть указан только для необязательных полей, которые не планируется заполнять в процессе загрузки.

#### Взять из файла

Основной способ получения значения реквизита. При такой настройке указывается название поля в файле, из которого нужно получать значение.

#### Установить в значение

Задается фиксированное константное значение для заполнения реквизита при загрузке.

#### Рассчитать по алгоритму

Описывается алгоритм на встроенном языке, с помощью которого вычисляется значение поля. Пример алгоритма для заполнения строкового поля текстом, в котором содержится текущая дата:

Сам алгоритм:

[Копировать в буфер обмена](javascript:)

Результат \= "Создано загрузкой " +  ТекущаяДата();

В алгоритме доступны структуры:

-   ДополнительныеСвойства - для передачи произвольных значений в пределах данного объекта

-   Параметры - явно добавленные в форме редактирования алгоритма параметры

Пример алгортима с использованием структуры ПоляФайла:

## Мониторинг состояния загрузки

Рабочее место позволяет:

\- Оценить общее состояние произведенной загрузки по Источнику данных.

\- Просматривать возникшие ошибки с группировками: «По типам данных», «По типам проблем», «По файлам».

\- Просматривать детальную информацию по возникшим ошибкам, включая в ряде случаев, значения полей из файла.

\- Произвести «Быстрое сопоставление» идентификатора объекту информационной базы.

\- Открыть проблемный объект.

\- После анализа и исправления ошибок – запустить повторную загрузку.

При выполнении загрузки, если в каталоге отсутствуют файлы, загрузка получает состояние “Нет данных для загрузки”:

Наименование этапа спецификации не является обязательным полем для настройки. Если оно не задано, то будет сформировано при загрузке автоматически по названию подразделения.

Если для материала реквизит “Производится в процессе” установлен в “Истина” и “Идентификатор вложенной технологии” не задан либо имеет пустое значение, то материал считается производимым полуфабрикатом, с автовыбором спецификации.

Если для этапа реквизит “Производство на стороне” установлен в “Истина”, то для него не будут создаваться операции, даже если их перечень присутствует в файле. При этом, необходимые реквизиты самого этапа будут заполнены по первой строке производственного процесса.

## Файлы загрузки

### Изделия и материалы

Описываются в файлах products\*.xml, расположенных в каталогах для загрузки.

Обрабатываются в первую очередь. Содержат данные о материалах, ДСЕ, продукции, которые преобразуются в элементы справочников «Номенклатура» и «Характеристики». Имеет одноуровневую структуру.

**Обязательно** содержат «Идентификатор» выгружающей системы, по которому система сможет идентифицировать ранее загружавшиеся позиции.

Могут содержать информацию о Наименовании, Единице измерения а также любые другие поля, необходимые для создания и заполнения номенклатурной позиции. Конкретные названия реквизитов в файлах могут быть любыми и определяются настройками загрузки. Для настроек, приведенных в демо-базе, подходит вот такой пример:

  <Product id="PDM1" prod\_type="Материалы основные" prod\_name="PDM Материал 1" munit="шт"/>
  <Product id="PDM2" prod\_type="Материалы основные" prod\_name="PDM Материал 2" munit="шт"/>
  <Product id="PDM3" prod\_type="Полуфабрикаты" prod\_name="PDM Полуфабрикат 1" munit="шт"/>
  <Product id="PDM4" prod\_type="Полуфабрикаты" prod\_name="PDM Полуфабрикат 2" munit="шт"/>
  <Product id="PDM5" prod\_type="Продукция" prod\_name="PDM Продукция 1" munit="шт"/>
  <Product id="PDM6" prod\_type="Продукция" prod\_name="PDM Продукция 2" munit="шт"/>
  
  <!-- Пример описания номенклатуры с характеристиками -->
  <!-- В настройках загрузки важно включить поиск по наименованию, чтобы не создавались новые записи номенклатуры -->

  <!-- Важно: у каждой пары Номенклатура,Характеристика свой идентификатор (тут поле id) -->
  <Product id="PDM7" prod\_type="Лакокрасочные материалы" prod\_name="PDM Краска с характеристиками" char\_name="Красная" munit="шт"/>

Преобразуется в элементы справочников Виды рабочих центров

### Составы изделий

Описываются в файлах bom\*.xml и обрабатываются после загрузки номенклатуры и оборудования. Каждый такой файл может содержать данные о материальном составе изделий для формирования одной или нескольких спецификаций. Преобразуется в элементы справочника Ресурсные спецификации с заполнением табличной части Материалы и работы. Таким образом, сочетание файлов products и bom позволяет получить черновики спецификаций, содержащих лишь составы изделий. Загрузка производственного процессе в спецификации делается при обработке последующих очередей файлов.

Структура - двухуровневая: уровень “шапки” состава и уровень материалов.

Обязательно содержит «Идентификатор изделия», «Идентификатор технологии» и «Идентификатор материала» выгружающей системы.

Может содержать информацию о Наименовании спецификации, Количестве материалов, сроке действия и любые другие поля, необходимые для создания и заполнения материального состава изделия.

### Технология производства

Описывается в файлах technology\*.xml. Содержат данные о технологии производства и нормировании и используются для наполнения ресурсных спецификаций описанием производственного процесса. Из этих файлов загружаются этапы спецификации, технологические операции, трудозатраты и при необходимости виды работ сотрудников. Трудозатраты заполняются по одной строчке на каждую операцию.

Файл может иметь двухуровневую (технология-операция) или трехуровневую (технология-этап-операция) структуру.

Двухуровневая структура содержит только последовательности технологических операций, без описания этапов производства. В этом случае этапы формируются автоматически из технологического процесса по цехозаходам. То есть если на очередной операции происходит смена цеха относительно предыдущей, она начинает новый этап.

Пример такого описания:

[Копировать в буфер обмена](javascript:)

<?xml version="1.0" encoding="windows-1251"?>
<Export>
  <!-- Пример двухуровневого описания: технология-операция -->
  <Technology bom\_id="sp001">  
    <!-- обратите внимание - по bom\_id связывается со спецификациями, описанными в BOM\*.xml -->
    <!-- В этом варианте этапы будут сформированы автоматически по цехозаходма -->
    <Operation workshop="Цех сборо-сварки" qty="10" oper\_name="Сварочная операция 1" labor\_id="9000" labor\_name="Сварка" />
    <Operation workshop="Цех сборо-сварки" qty="1" oper\_name="Сварочная операция 2" labor\_id="9000" labor\_name="Сварка" />
    <!-- В этом месте меняется цех, поэтому будет образован новый этап автоматически -->
    <Operation workshop="Цех упаковки" qty="1" oper\_name="Упаковочная операция 1" labor\_id="0830" labor\_name="Упаковывание" />
    <Operation workshop="Цех упаковки" qty="1" oper\_name="Упаковочная операция 2" labor\_id="0830" labor\_name="Упаковывание" />
  </Technology>
  <Technology bom\_id="sp002">  
    <!-- Вторая спецификация. В одном файле их может быть любое количество -->
    <Operation workshop="Цех сборо-сварки" qty="1" oper\_name="Сварочная операция 1" labor\_id="9000" labor\_name="Сварка" />
    <!-- В этом месте меняется цех, поэтому будет образован новый этап автоматически -->
    <Operation workshop="Цех упаковки" qty="1" oper\_name="Упаковочная операция 1" labor\_id="0830" labor\_name="Упаковывание" />
  </Technology>
</Export>

### Разрешения на замену

Разрешения на замену описываются в файлах replacements\*.xml. Файл имеет двухуровневую структуру: документ-строчки. На уровне строчек описываются как оригинальные материалы, так и аналоги. Чем является конкретная запись, определяется реквизитом Материал/аналог. Если значение 0, то это оригинальный материалв, 1 – аналог.

Пример файла replacements\_demo.xml:

[Копировать в буфер обмена](javascript:)

<?xml version="1.0" encoding="windows-1251"?>
<Export>
  <!-- Разрешение на замену один к одному -->
  <Doc doc\_id="00-001">
    <!-- оригинал (rec\_type 0) -->
    <Material mat\_id="pdm1" qty="1" rec\_type ="0"/>
    <!-- аналог (rec\_type 1) -->
    <Material mat\_id="pdm2" qty="1" rec\_type ="1"/>
  </Doc>
  <!-- Разрешение на замену несколько на несколько -->
  <Doc doc\_id="00-002">
    <Material mat\_id="pdm1" qty="1" rec\_type ="0"/>
    <Material mat\_id="pdm3" qty="2" rec\_type ="0"/>
    <Material mat\_id="pdm2" qty="3" rec\_type ="1"/>
    <Material mat\_id="pdm4" qty="4" rec\_type ="1"/>
  </Doc>
</Export>

## Ограничения механизма

В версии 2.5.26 не поддерживаются следующие возможности:

-   множественная продукция в спецификации
-   спецификации иных типов кроме Изготовление, сборка
-   этапы без операций
-   несколько трудозатрат на одну операцию

В дальнейшем планируется снимать ограничения по мере развития механизма.
