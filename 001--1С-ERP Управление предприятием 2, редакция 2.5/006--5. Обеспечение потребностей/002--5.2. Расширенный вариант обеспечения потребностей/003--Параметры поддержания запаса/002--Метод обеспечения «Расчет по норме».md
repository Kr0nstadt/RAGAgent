# Расширенный вариант обеспечения потребностей

Сценарий обеспечения потребностей на складе:

■ Настройка способов обеспечения потребностей:

○ установка схемы обеспечения (для каждого склада задается способ обеспечения потребностей);

○ установка взаимосвязи схемы обеспечения с номенклатурными позициями.

■ Настройка поддержания запасов на складе:

○ добавление номенклатурных позиций, для которых необходимо поддерживать запасы;

○ установка методов обеспечения и параметров поддержания запасов для добавленных номенклатурных позиций.

■ Формирование заказов по потребностям в соответствии с заданными настройками обеспечения потребностей.

## Способы обеспечения потребностей

Способ обеспечения потребностей – исчерпывающий набор параметров для формирования заказов, прогнозирования возможной даты отгрузки заказов. Способ обеспечения потребностей определяет, каким образом и из каких источников будет удовлетворяться потребность в номенклатуре. Например, номенклатура будет закупаться у поставщика, перемещаться с другого склада, производиться или другое.

Способы обеспечения потребностей регистрируются в списке Склад и доставка – Настройки и справочники – Обеспечение потребностей – Способы обеспечения потребностей.

В списке хранятся все варианты способов обеспечения, которые применяются на предприятии. Есть возможность задавать обобщенные способы обеспечения (покупка у поставщика, перемещение и т. д.) и затем уточнять конкретные данные на этапе формирования потребностей. Если заранее известны условия, при которых осуществляется поставка товаров (поставщик, соглашение, срок исполнения заказа и т. д.), то эти условия можно зафиксировать в карточке способа обеспечения потребностей.

### Параметры способов обеспечения потребностей

В форме карточки Способ обеспечения потребностей указываются параметры обеспечения потребностей.

Тип обеспечения - параметр, определяющий, каким образом будет удовлетворяться потребность в номенклатуре и какие заказы необходимо формировать с целью обеспечения этой потребности.

Для всех способов обеспечения опционально можно указать организацию и подразделение, используемые для автоматической подстановки в формируемые заказы (на закладке Оформление заказов в форме карточки способа обеспечения потребностей). Подразделение указывает, какое из подразделений предприятия осуществляет поставку по данному способу и, соответственно, должно обеспечивать потребности в номенклатуре, обеспечиваемой данным способом.

Способ обеспечения описывает правило формирования заказов для одной или нескольких товарных позиций. Если у логиста множество одновременно действующих правил, то каждое правило необходимо описать в форме способа обеспечения.

Если необходимо заполнять поставщика в формируемом заказе, то можно создать один способ обеспечения без указания поставщика, тогда в рабочем месте Формирование заказов по потребностям поставщик заполнится по статистике закупок (по ранее созданным заказам поставщику данной товарной позиции).

Если два товара закупаются у разных поставщиков, то это не означает, что у товаров разные способы обеспечения. В таком случае рекомендуется создать один способ обеспечения с незаполненным поставщиком. Два отдельных способа обеспечения требуются, если разные сроки поставок. Исходя из срока поставки рассчитываются минимальный и максимальный запас товара, если для товара задан метод поддержания запаса «расчет по норме» или «расчет по статистике».

По каждой строке в рабочем месте Формирование заказов по потребностям на шагах 3,4 можно изменить способ обеспечения. При этом стоит учитывать, что установленный способ обеспечения будет использоваться только для формирования текущего заказа. В дальнейшем для номенклатуры будет использоваться способ обеспечения, заданный в качестве индивидуального способа обеспечения потребностей или способ обеспечения, заданный в схеме обеспечения. Для изменения способа обеспечения можно использовать рабочее место Настройка способов обеспечения потребностей.

Кроме того, источник обеспечения следует уточнить для тех способов, в которых он не задан. Например, может быть указан способ обеспечения «Закупка в другом городе», без уточнения поставщика. В момент формирования заказа, когда уже точно известен поставщик, его необходимо указать в качестве источника обеспечения в рабочем месте Формирование заказов по потребностям на шагах 3,4.

#### Покупка

Тип обеспечения Покупка используется, если номенклатура закупается у поставщика. Данный способ обеспечения позволяет формировать заказы поставщику.

Срок покупки – срок, за который может быть исполнен заказ на покупку, созданный по данному способу. Определяет период между датой формирования заказа и датой поступления товаров (тары, работ) на склад. Фиксация срока исполнения заказа позволяет спланировать обеспечение заблаговременно, чтобы потребности были обеспечены в срок.

Срок – это экспертная оценка, срок может быть уточнен как при формировании заказов, так и в сформированном заказе.

Срок исполнения заказа отсчитывается по рабочим дням календаря предприятия. Например, если сегодня понедельник и планируется заказ по способу обеспечения со сроком исполнения 7 дней, а суббота и воскресенье – выходные дни по календарю предприятия, то поступление заказа будет запланировано на следующую среду, через 7 рабочих дней. Срок исполнения позволяет определить дату ближайшего возможного поступления товаров (тары, работ).

В качестве источника обеспечения потребностей можно указать поставщика (режим С одним поставщиком), который будет использоваться для подстановки в формируемые заказы в рабочем месте Формирования заказов по потребностям. Также можно указать соглашение, определенное для работы с одним поставщиком. При выборе соглашения в способе обеспечения из соглашения заполняются организация, вид цены, в разрезе которого ведется учет цен поставщика, а также поле «Срок покупки». Параметры планирования данного способа обеспечения будут применяться для формирования заказа только одному поставщику.

Если параметры планирования данного способа обеспечения применяются для заказа различным поставщикам, используются любые поставщики) (в способе обеспечения потребностей не задан поставщик), то используется режим С несколькими поставщиками.

Если способ обеспечения потребностей используется для работы с несколькими поставщиками или способ обеспечения потребностей не задан, то в рабочем месте Формирование заказов по потребностям на шагах 3,4 для каждого товара заполнение источника обеспечения (поставщика)  выполняется по статистике с использованием следующего алгоритма:

■ если есть один проведенный заказ поставщику, то автоматически будет установлен поставщик по этому заказу;

■ если есть два проведенных заказа поставщикам - поставщик подставляется, если он совпадает в обоих заказах. Иначе значение поставщика остается пустым.

■ если есть три и более проведенных заказа поставщикам то:

○ документы «Заказ поставщику» сортируются по датам;

○ берутся три последние даты из документов;

○ берутся партнеры из трех заказов на указанные даты. Если два из трех или все три поставщика совпадают, то поставщик автоматически заполняется. Иначе значение поставщика остается пустым.

Заполнение соглашения определяется по поставщику, из соглашения подбирается валюта и вид цены, по которому заполняются цены номенклатуры в рабочем месте Формирование заказов по потребностям.

Заполнение поставщика, соглашения и валюты по статистике зависит от настройки использования механики заполнения реквизитов документов по статистике (опция Заполнять реквизиты документов по статистике в персональных настройках текущего пользователя).

Если в персональных настройках пользователя отключено использование статистики для заполнения реквизитов документов, то статистика не будет использоваться для определения поставщика, соглашения и валюты в рабочем месте Формирование заказов по потребностям.

#### Перемещение

Тип обеспечения Перемещение используется, если номенклатура обеспечивается путем перемещения с одного склада на другой склад.

Позволяет формировать заказы на перемещение и заказы материалов в цеховые кладовые.

В качестве источника обеспечения потребностей можно указать распределительный центр (склад-отправитель), с которого будут перемещаться товары (режим Для работы с одним складом), и  который будет использоваться для подстановки в формируемые заказы в рабочем месте Формирования заказов по потребностям. Параметры планирования данного способа обеспечения будут применяться для перемещения только с распределительного центра.

Если способ обеспечения потребностей применяется для работы с несколькими складами, то используется режим Для работы с несколькими складами. Параметры планирования будут применяться для перемещения с различных складов.

Срок перемещения - срок исполнения заказа на перемещение. Поставщиком товаров является склад-отправитель. Склад-отправитель имеет договоренность с логистом, что в течение этого срока товар на складе-отправителе соберут, отправят и товар дойдет до склада-получателя. Срок используется в рабочем месте Формирования заказов по потребностям. По этому сроку рассчитывается дата ближайшего возможного поступления товаров - дата поступления на склад-получателя, если логист сформирует заказ текущим днем.

Длительность перемещения - часть срока перемещения, время, затрачиваемое от момента отправки товара на складе-отправителе, до момента получения товара на складе-получателе.

Если на складе отправителе запас товара есть всегда, то срок перемещения необходимо задавать равным длительности перемещения. Если на складе отправителе товара может не быть, то срок перемещения должен дополнительно включать в себя срок покупки товара на складе-отправителе.

#### Сборка

Тип обеспечения Сборка, используется, если номенклатура обеспечивается путем сборки новых комплектов из комплектующих. Данный способ обеспечения позволяет формировать заказы на сборку.

Срок сборки - срок, за который может быть исполнен заказ на сборку. Определяет период между датой формирования заказа и датой сборки комплектов. Фиксация срока исполнения заказа позволяет спланировать обеспечение заблаговременно, чтобы потребности были обеспечены в срок. По этому сроку рассчитывается дата ближайшей возможной сборки комплектов.

Длительность сборки - часть срока сборки, время, затрачиваемое от момента начала сборки, до момента окончания сборки. Если на складе сборки есть запас комплектующих, то срок сборки необходимо задавать равным длительности сборки. Если на складе сборки комплектующих нет, то срок сборки должен дополнительно включать в себя срок обеспечения (покупки) комплектующих.

#### Собственное производство

Тип обеспечения Собственное производство, используется, если продукция поступает на склад в результате производства, обеспечение потребностей осуществляется путем выпуска готовой продукции. Данный способ обеспечения потребностей позволяет формировать заказы на производство.

Срок производства - срок, за который может быть исполнен заказ на производство. Определяет период между датой формирования заказа и датой выпуска продукции (работ). По этому сроку рассчитывается дата ближайшего возможного выпуска продукции (работ).

В качестве источника обеспечения потребностей можно указать подразделение-диспетчера (режим С одним подразделением-диспетчером), которое будет использоваться для подстановки в формируемые заказы в рабочем месте Формирования заказов по потребностям. Параметры планирования данного способа будут применяться для производства только в одном диспетчирующем подразделении.

#### Производство силами переработчика

Тип обеспечения Производство силами переработчика, используется, если продукция производится силами переработчика, обеспечение потребностей осуществляется путем выпуска готовой продукции (полуфабрикатов) сторонней организацией, именуемой Переработчик. Данный способ обеспечения потребностей позволяет формировать заказы переработчику.

Срок переработки - срок, за который может быть исполнен заказ переработчику. Определяет период между датой формирования заказа и датой получения продукции. По сроку рассчитывается дата ближайшего возможного получения продукции.

В качестве источника обеспечения потребностей можно указать переработчика (режим С одним переработчиком), который будет использоваться для подстановки в формируемые заказы в рабочем месте Формирования заказов по потребностям.

#### Правило формирования заказов

Правило формирования заказов – определяет момент формирования заказа и обеспечиваемый период, потребности которого будут включены в заказ. Поддерживаются правила формирования заказов:

■ По точке заказа (заказ при достижении точки заказа) – заказы формируется в любой день, при наступлении точки заказа. Позволяет определить дату поставки по мере расхода текущего запаса, момент прохождения «точки заказа». Календарные даты поставок заранее неизвестны. Определяется дата, не позднее которой нужно сформировать заказ, чтобы своевременно обеспечить потребности (не допустить исчерпания запаса). В процессе обеспечения к заказу предлагаются номенклатурные позиции, для которых рассчитанная дата начала процесса обеспечения совпала с текущей датой. Точка заказа для товара наступает, когда остаток снижается до минимального запаса, а также когда приближается дата отгрузки потребности по заказу (на срок исполнения заказа). Система будет предлагать к заказу номенклатуру, по которой необходимо сформировать заказы сегодня (чтобы вовремя обеспечить потребности в номенклатуре по текущим заказам или с учетом предполагаемого потребления и текущих остатков на складе).

○ Параметр Период, обеспечиваемый заказом учитывает график работы предприятия (а не график работы склада):

□ Определенное количество дней – можно задать произвольное количество дней с учетом графика работы предприятия. Обеспечиваемый период отсчитывается от Даты поступления по заказу с учетом графика работы предприятия и используется для расчета параметров поддержания запасов («максимальный запас» при методах поддержания запасов «Расчет по норме», «Расчет по статистике»), исходя из количества рабочих дней склада в периоде и среднедневного потребления.

□ Не ограничен - обеспечиваемый период не рассчитывается, можно использовать только для товаров, максимальный запас которых устанавливается вручную (при методе поддержания запасов «Min – max»), либо запасы которых не поддерживаются.

■ По расписанию (заказ по графику) - календарные даты поставок фиксированные. Поставки происходят в заранее известные даты. Заказы формируются по фиксированным датам, исходя из заданной периодичности поставок и срока исполнения заказа:

○ Каждые. Можно указать правило получения дат поставки. При расчете дат по правилу график работы предприятия не учитывается.

○ График поставок. Можно указывать даты поставки, создав для этого график работы.

При правиле формирования заказов По расписанию можно задавать произвольное количество дней с учетом графика работы предприятия с использованием параметра Период, обеспечиваемый заказом, значение которого отсчитывается от Даты поступления по заказу и используется при расчете количества к заказу:

■ Определенное количество дней – можно задать произвольное количество дней с учетом графика работы предприятия. Обеспечиваемый период отсчитывается от даты поступления по заказу с учетом графика работы предприятия и используется для расчета параметров поддержания запасов («максимальный запас» при методах поддержания запасов «Расчет по норме», «Расчет по статистике»), исходя из количества рабочих дней склада в периоде и среднедневного потребления.

■ До даты следующий поставки – соответствует функциональности ранних версий, при которой максимальный запас рассчитывался только так, чтобы товара хватило до следующей поставки (при методах поддержания запасов «Расчет по норме», «Расчет по статистике»).

■ Не ограничен – обеспечиваемый период не рассчитывается, можно использовать только для товаров, максимальный запас которых устанавливается вручную (при методе поддержания запасов «Min – max»), либо запасы которых не поддерживаются.

Ограничивать период нужно только для товаров, запас которых поддерживается расчетным путем (метод поддержания запасов «Расчет по норме» или «Расчет по статистике»). Для товаров, поддерживаемых методом поддержания запасов «Min – Max», и обеспечения заказов на отгрузку параметр Период, обеспечиваемый заказом, не используется. В таком случае можно устанавливать значение Не ограничен.

В настройках Расчет ближайшего цикла обеспечения расчет даты поставки (Дата поступления по заказу):

■ По расписанию – График поставок - определяется минимально возможная дата поступления по заказу, исходя из Срока исполнения заказа, например, сегодня 24.02 (понедельник), по указанному графику поставка осуществляется каждые 6 дней в неделю (ПН, ВТ, СР, ЧТ, ПТ, СБ), ближайшая дата поставка 03.03 (понедельник), исходя из указанного графика поставки и с учетом срока исполнения заказа 6 дн.

■ По расписанию – Каждые - определяется ближайшая к найденной дате дата поступления по заказу, исходя из периодичности графика: например, сегодня 10.01 (пятница), поставка осуществляется 1 раз в неделю, начиная с 10.01 (пятница), ближайшая дата поставки через неделю 17.01 (пятница). Дата формирования заказа поставщику - от даты поступления по заказу 17.01 вычитается срок исполнения заказа (3 дн.) по графику работы предприятия (за вычетом выходных дней), получаем 14.01 (вторник).

Гарантированной срок обеспечения – запас в днях относительно срока исполнения заказа. Это время на то, чтобы логист увидел потребность, зафиксированную потребителем и начал планировать ее обеспечение. Используется при расчете плановой даты обеспечения потребности, при отсутствии запаса товара (тары) на складе (работ в подразделении) и в ожидаемых поступлениях. Это срок, в течение которого гарантируется обеспечение потребности в товаре на складе, в случае ее возникновения. Данный срок сообщает как плановую дату поставки для потребностей, обеспечение которых еще не спланировано. Как правило, гарантированный срок обеспечения устанавливается с запасом относительно срока исполнения заказа. Гарантированный срок используется в качестве плановой даты поступления для отображения в обработке состояния обеспечения необеспеченного заказа на отгрузку.

Расчет даты отгрузки заказов по гарантированному сроку обеспечения:

■ От текущей даты откладывается гарантированный срок обеспечения, 09.01 (четверг) + 5 дн. по графику предприятия (за вычетом выходных дней) = 16.01 (четверг).

■ Ближайшая дата поставки по расписанию 14.01 (вторник).

■ Программой берется большая из двух дат, получаем 16.01 (четверг).

#### Устранение дефицита при заказе по графику (расписанию)/Комбинированный заказ

Предусмотрена возможность осуществлять плановую поставку по фиксированным датам, а до наступления даты планового формирования заказа автоматически отслеживать дефицит. Для возможности комбинированного заказа устанавливается правило формирования заказа По точке заказа и По расписанию в карточке способа обеспечения потребностей.

Если при этом установить вариант обеспечиваемого периода Период, обеспечиваемый заказом - До даты следующей поставки, то товары, запас которых достиг точки заказа, будут заказаны в количестве, достаточном до даты ближайшей плановой поставки (если для товара установлен метод поддержания запасов «Расчет по норме» или «Расчет по статистике»).

Если в способе обеспечения потребностей задано правило формирования заказов По расписанию и дополнительно установлен флаг По точке заказа, то до наступления даты заказа по графику, к заказу будут предлагаться товары, достигшие точки заказа. В противном случае, товары будут предлагаться к заказу только при наступлении даты заказа по расписанию.

В текущем сеансе работы можно вручную указать, что товары необходимо заказать сегодня. В этом случае на следующих шагах программа предложит к заказу такие товары, даже если точка заказа товара не достигнута.

### Индивидуальные настройки способов обеспечения потребностей

Для индивидуальной настройки способов обеспечения потребностей номенклатуры предназначено рабочее место Настройка способов обеспечения потребностей. Рабочее место доступно по соответствующей гиперссылке в карточке номенклатуры.

Рабочее место также доступно по соответствующей гиперссылке в карточке склада.

В настройках способа обеспечения потребностей, доступных из карточки склада, для номенклатуры можно заполнить упаковку заказа, которая будет использоваться для округления количества товара в заказе на обеспечение потребностей (команда Заполнить упаковку заказа).

Для анализа товаров, включенных в схему обеспечения, и отображения всех складов, на которых эти товары обеспечиваются, используется отчет Товары, включенные в схему обеспечения.

В отчете индивидуальные настройки способов обеспечения потребностей, заданные для номенклатуры, выделяются синим цветом. Из отчета можно перейти к форме настроек способов обеспечения номенклатуры на всех складах предприятия путем расшифровки ячейки двойным щелчком левой кнопки или двойным щелчком правой кнопки мыши (Перейти – Изменить способ обеспечения потребностей).

## Схемы обеспечения потребностей

Схема обеспечения потребностей - шаблон типового процесса, отражающий движение товарно-материальных ценностей по складам, подразделениям. Схема описывает все этапы процесса от момента поступления товара до отгрузки. Например, «Закупка на склад» – «Перемещение в производственный цех» – «Отгрузка из производственного цеха в производство»; «Закупка на склад» – «Отгрузка с того же склада». Позволяет упростить описание параметров обеспечения товаров по складам за счет группировки товаров с однотипным процессом обеспечения по схемам. Применяется для предприятий с разветвленной структурой (несколько складов, несколько производственных цехов).

Схемы обеспечения потребностей регистрируются в списке Склад и доставка – Настройки и справочники – Схемы обеспечения.

Доступность работы со схемами обеспечения потребностей определяется функциональной опцией НСИ и администрирование – Настройка НСИ и разделов – Склад и доставка – Обеспечение потребностей – Расширенное.

Задать схему обеспечения потребностей можно как в разрезе склада, так и в разрезе формата магазинов (складов).

Предусмотрены различные режимы настройки схемы обеспечения потребностей для складов (на закладке Склады):

■ Режим По форматам – позволяет установить схему обеспечения для формата магазинов (складов). Если схема обеспечения установлена для формата магазинов, то она будет действовать в отношении всех складов, относящихся к данному формату. Также для склада можно установить способ обеспечения, отличный от способа обеспечения формата, к которому принадлежит склад.

■ Режим По иерархии – позволяет установить схему обеспечения в разрезе формата магазинов (складов) как для группы складов, так и для каждого склада в отдельности. Чтобы задать способ обеспечения потребностей для группы складов, необходимо выделить склады, входящие в состав одной группы.

Информация о том, какое количество товаров обеспечивается в соответствии с заданной схемой обеспечения, показывается в шапке формы Схема обеспечения (надпись Используется для товаров).

Пример схемы обеспечения потребностей на складах предприятия представлен на рисунке.

Например, для одного товара задана схема обеспечения. Эта схема включает все склады, на которые поступает данный товар. Для каждого склада схемы обеспечения заданы способы обеспечения потребностей. Если на всех складах способы обеспечения для второго товара такие же, как и для первого, то второй товар включаем в уже созданную схему обеспечения. Если нет, то создаем отдельную схему для второго товара и описываем все пары «Склады – Способы обеспечения потребностей» для второго товара и т.д.

Если первая схема подходит для второго товара, кроме одного звена цепи, то это исключение можно задать в рабочем месте по настройке способов обеспечения потребностей, установив способ обеспечения для второго товара на конкретном складе. Настройка исключений не рекомендуется, так как это затрудняет управление схемами обеспечения.

Если нет устойчивых схем обеспечения для товара, то рекомендуется задавать индивидуальный способ обеспечения потребностей непосредственно для товара в рабочем месте по настройке способов обеспечения потребностей.

Товар и тара обеспечиваются в соответствии со схемами обеспечения склада. Схема, в соответствии с которой будет обеспечиваться товар/тара, назначается в карточке номенклатурной позиции (поле Схема обеспечения). Для товара/тары может быть задана только одна схема обеспечения склада.

Потребность в работах обеспечивается в соответствии со способом обеспечения потребностей. Способ обеспечения потребностей для типа номенклатуры Работа задается в карточке номенклатуры (поле Способ обеспечения потребностей).

Обеспечивается возможность включения подразделения в схему обеспечения потребностей. Если для номенклатуры поддерживается запас на складе, который выступает в роли цеховой кладовой подразделения, то такой товар будет поступать в цех из кладовой, а не со склада, указанного для подразделения на закладке Производственные подразделения.

## Параметры поддержания запаса

Для решения задачи формирования оптимального запаса на складах поддерживаются различные методы обеспечения потребностей и соответствующие им параметры поддержания запасов.

Метод обеспечения – cтратегия, в соответствии с которой обеспечиваются потребности для поддержания запасов на уровне неснижаемого остатка на складе и обеспечения заказов на отгрузку.

Скорейшее удовлетворение возникшей потребности из имеющегося в наличии запаса реализуется различными методами обеспечения:

■ Min – Max;

■ Расчет по норме;

■ Расчет по статистике.

Данные методы обеспечения позволяют поддерживать запасы на уровне неснижаемого остатка.

### Метод обеспечения «Min – Max»

Если не ведется статистика потребления товаров, то рекомендуется использовать метод обеспечения Min – Max. Использование данного метода позволяет поддерживать уровень остатка на складе в соответствии с желаемым минимальным запасом.

При использовании этого метода страховой запас, статистика продаж не учитываются при анализе наступления точки заказа.

Поддержание запаса методом обеспечения Min – Max осуществляется в соответствии с определенными параметрами (эти параметры задаются пользователем вручную):

■ Максимальный запас – количество товаров на складе сразу после пополнения запаса;

■ Минимальный запас – количество товаров на складе, при достижении которого необходимо формировать заказ.

Потребность в заказе товара будет возникать в тот момент, когда остаток товара на складе меньше минимального остатка либо равен ему. При снижении запаса до минимального количества система будет предлагать к заказу количество товара, равное желаемому максимальному запасу.

Значения параметров поддержания запаса задаются вручную, опираясь на Параметры обеспечения потребностей.

### Метод обеспечения «Расчет по норме»

Если требуется поддерживать уровень запаса на складе в соответствии с нормой потребления товаров в день, то для этих целей рекомендуется использовать метод обеспечения Расчет по норме.

При использовании метода Расчет по норме прогнозируется расход материальных ценностей согласно дневной норме потребления.

Поддержание запаса методом Расчет по норме осуществляется в соответствии с параметрами поддержания запаса:

■ Норма потребления в день – количество товаров, потребляемое за один день.

■ Минимальный запас – количество товаров на складе, при достижении которого необходимо формировать заказ.

■ Максимальный запас – количество товаров на складе сразу после пополнения запаса.

■ Страховой запас – часть минимального запаса, устанавливаемая вручную. Оставшаяся часть минимального запаса рассчитывается автоматически по норме потребления на срок поставки.

Норма потребления в день указывается пользователем вручную. Расчет минимального и максимального запасов осуществляется индивидуально для номенклатуры и производится автоматически по заданной норме потребления в день.

Минимальный запас рассчитывается на срок исполнения заказа – количество товаров, которое обеспечит потребность на срок поставки товаров. Максимальный запас рассчитывается на обеспечиваемый период – количество товаров, которое обеспечит потребность на этот период (учитываются параметры, заданные для способа обеспечения потребностей).

При использовании данного метода будет предложено сформировать заказ тогда, когда текущего остатка товаров (за вычетом страхового) будет хватать не более чем на срок исполнения заказа по способу обеспечения, заданному для данного товара.

При снижении запаса товара до минимального количества, необходимого на срок поставки, система будет предлагать к заказу количество, равное максимальному запасу, необходимому на обеспечиваемый период.

Количество к заказу по данному методу рассчитывается таким образом, чтобы товара хватило на заданный срок обеспечения или до указанной даты. Количество товара, которое необходимо обеспечить, рассчитывается как среднедневное потребление, умноженное на количество дней до следующей поставки или на количество дней в обеспечиваемом периоде (это зависит от настроек, указанных в способе обеспечения). Расчет производится по формулам:

Максимальный запас = Норма потребления в день \* Обеспечиваемый период + Страховой запас.

Минимальный запас = Норма потребления в день \* _Срок поставки (количество рабочих дней в графике работы склада за период: Текущая дата – Дата поставки) + Страховой запас_.

Минимальный и максимальный запасы рассчитываются, опираясь на Параметры обеспечения потребностей.

### Метод обеспечения «Расчет по статистике»

Если статистика расходов известна и отклонение от рассчитанного потребления в разные дни невелико, рекомендуется использовать метод обеспечения потребностей Расчет по статистике.

Расчет статистики потребления позволит определить наиболее продаваемые товары на основе данных о среднедневном потреблении и величине отклонения от него. Это поможет правильно определить нужный метод обеспечения потребностей. Например, если товар продается стабильно (отклонение от среднедневного потребления небольшое), то можно использовать метод обеспечения Расчет по статистике. Если же товар имеет нестабильное потребление, то рекомендуется использовать методы обеспечения Min – Max или Расчет по норме.

При этом методе используется накопленная статистика потребления товаров. Прогнозируется расход материальных ценностей согласно рассчитанному по статистике среднедневному потреблению.

При методе обеспечения Расчет по статистике выполняется индивидуальный расчет для номенклатуры параметров поддержания запаса:

■ Среднедневное потребление – количество товаров, потребляемое за один день.

■ Минимальный запас – количество товаров на складе, при достижении которого необходимо формировать заказ.

■ Максимальный запас – количество товаров на складе сразу после пополнения запаса.

При использовании метода обеспечения Расчет по статистике можно задать дополнительный параметр поддержания запаса – Страховой запас, позволяющий покрыть возможные всплески спроса (по сравнению с рассчитанной статистикой) и обеспечить запас номенклатурных позиций при срыве срока пополнения запаса.

При использовании данного метода будет предложено сформировать заказ тогда, когда текущего остатка товаров (за вычетом страхового) будет хватать не более чем на срок исполнения заказа по способу обеспечения. Количество к заказу по данному методу рассчитывается таким образом, чтобы товара хватило на заданный срок обеспечения или до указанной даты.

При снижении запаса товара до минимального количества, необходимого на срок пополнения запаса, к заказу будет предложено максимальное количество товара на обеспечиваемый период.

### Режимы обеспечения потребностей по заказам на отгрузку

Режим обеспечения потребностей по заказам на отгрузку определяется настройкой Потребности заказов к отгрузке в форме Параметры поддержания запаса, доступной по кнопке Заполнить – Поддержание запаса в рамках рабочего места Настройка поддержания запасов.

Режим обеспечения заказов на отгрузку учитывается при расчете количества товаров, которое необходимо заказать для обеспечения потребностей по текущим заказам на отгрузку в рамках рабочего места Формирование заказов по потребностям.

Обеспечение потребностей по заказам на отгрузку может осуществляться в следующих режимах:

■ Обеспечивать за счет запасов. Все товары на складе используются и для розницы и для оптовой продажи. Решается задача закупки для поддержания запаса и закупленные товары распределяются на спрос по заказам на отгрузку:

○ На шаге 3 при поддержании запасов на складе (всего остатка на складе): Остаток = В наличии (В резерве + Свободный (доступный) остаток); Заказы к поступлению = Все не поступившие согласованные, подтвержденные заказы на поступление.

○ На шаге 4 при обеспечении заказов на отгрузку получаем, сколько заказов на отгрузку не обеспечено остатком на складе, не поступившими заказами и количеством к заказу на шаге 3: Обеспечено = Остаток (свободный (доступный)), распределенный на заказ + Заказы к поступлению, распределенные на заказ + К заказу на шаге 3 (обеспечено заполняется с учетом распределенных запасов на заказ, свободного остатка, заказов на поступление). К заказу = Требуется (количество по заказу) – Обеспечено. При этом в наличии может быть остаток, находящийся в резерве по другому заказу на отгрузку.

○ К заказу = Макс (Шаг 3 потребность в запасах, Шаг 4 потребность по заказам).

■ Обеспечивать независимо от поддержания запасов. На складе одна часть товара обеспечивается для розницы (свободный остаток), вторая часть - для заказов на отгрузку:

○ На шаге 3 при поддержании запасов (свободного остатка): Остаток = Свободный (доступный) остаток; Заказы к поступлению = Все не поступившие согласованные, подтвержденные заказы на поступление. Если есть заказы на отгрузку, то выполняется автоматическое распределение запасов на заказы, свободного остатка, заказов на поступление, в таком случае в колонках «Остаток» = 0 и «Заказы к поступлению» = 0. В колонке «Заказы к поступлению» ненулевое количество, если есть излишек обеспечения - свободный остаток за вычетом заказов с действием «К обеспечению» и отложенных заказов (с действием «Резервировать по мере», но дата отгрузки за границей периода обеспечения).

○ На шаге 4 при обеспечении заказов на отгрузку: Обеспечено = Свободный (доступный) остаток, распределенный на заказ + Заказы к поступлению, распределенные на заказ (обеспечено заполняется с учетом распределенных запасов на заказ, свободного остатка, заказов на поступление). К заказу = Требуется (количество по заказу) – Обеспечено.

○ К заказу = Шаг 3 потребность в запасах + Шаг 4 потребность по заказам.

В режиме обеспечения заказов на отгрузку Обеспечивать независимо от поддержания запасов - если есть излишек запаса (на шаге 3 Поддержание запасов), то этот излишек используется для обеспечения заказов (на шаге 4 Обеспечение заказов к отгрузке).

### Настройка поддержания запасов

Установка параметров поддержания запасов выполняется в рабочем месте Настройка поддержания запасов, доступном по одноименной гиперссылке в карточке номенклатуры, склада либо по ссылке Склад и доставка – Обеспечение потребностей.

Также рабочее место по настройке поддержания запасов доступно по гиперссылке Настроить поддержание запасов в рабочем месте Формирование заказов по потребностям.

Задачи, решаемые в рабочем месте по настройке поддержания запасов:

■ Установка параметров поддержания запасов на конкретном складе.

■ Установка параметров поддержания запасов на формат магазина (склада). Например, ввести одну строку параметров поддержания запасов по товару и тем самым настроить одинаковые параметры не на одном складе, а сразу на нескольких, на всех складах одного формата.

■ Установка параметров поддержания запасов на номенклатуру в целом (одинаковые для всех характеристик).

■ Установка одинаковых параметров поддержания запасов для сгруппированных номенклатурных позиций (возможна установка сразу для нескольких строк). Для этого предусмотрена произвольная группировка позиций в списке. Параметры поддержания группировки будут применяться ко всем товарам в составе группировки на различных складах.

Работа по настройке поддержания запасов организована в двух режимах:

■ Действующие параметры – добавляются товары, для которых необходимо поддерживать запасы; устанавливаются параметры поддержания запасов.

■ Рекомендации по изменению – выводится список товаров, по которым программа рекомендует изменить поддержание запаса. Программа автоматически выдает рекомендации, которые позволяют принять решение о необходимости поддержания запасов на складе по конкретным номенклатурным позициям. Рекомендуется поддерживать запас, если статистика расхода товара известна и отклонение от рассчитанного потребления не более 5%, и наоборот не поддерживать, если статистика расхода неизвестна или отклонение более 5%. Параметры расчета статистики потребления задаются при помощи команды (Еще - Настройка расчета статистики потребления). Среднедневное потребление и процент отклонения (Отклонение потребления, % = Среднедневное потребление/Среднеквадратичное отклонение) можно увидеть в крайних правых колонках таблицы.

Расчет рекомендаций по изменению параметров поддержания запасов выполняется следующими способами:

■ регламентным заданием в соответствии с настроенным расписанием «Расчет рекомендаций поддержания запасов»;

■ фоновым заданием, если не включено регламентное задание. Расчет будет выполняться при указании отбора по складу в рабочем месте Настройка поддержания запасов.

Добавление товаров и расчет рекомендаций доступны при установленном отборе по складу в шапке рабочего места Настройка поддержания запасов.

Установленный отбор по складу в рабочем месте означает:

■ не отображать строки, в которых значение склада не совпадает со значением в шапке;

■ заполнять автоматически этим складом значения склада для новых строк, добавляемых по команде Добавить товары.

Список товаров, по которым необходимо поддерживать запасы на складе, может быть добавлен следующими способами (кнопка Добавить товары):

■ с помощью стандартной обработки подбора товаров. Добавление происходит пономенклатурно из списка товаров. Для номенклатуры, у которой включен учет по характеристикам, добавятся общие параметры поддержания запаса по номенклатуре в целом, действующие для всех характеристик без индивидуальных параметров.

■ с помощью механизма отбора товаров по любым параметрам (по ценовым группам, по группам номенклатуры, по наличию на складе и т. д.). Добавление происходит по выбранным критериям. Для номенклатуры, у которой включен учет по характеристикам, добавятся индивидуальные параметры поддержания запаса без общих параметров по номенклатуре в целом.

■ с помощью механизма загрузки данных из внешнего файла произвольного формата. В момент загрузки из файла можно сразу задать значения минимального и максимального запасов для номенклатурных позиций.

Для товаров в момент их добавления (по команде Добавить товары – Подобрать товары или По отбору) по умолчанию устанавливается метод поддержания запаса Мin – Max, значения минимального запаса = 0 и максимального запаса = 0, режим обеспечения запасов Обеспечение за счет запасов.

Выбор метода обеспечения потребностей, режима обеспечения заказов на отгрузку и установка соответствующих параметров поддержания запасов выполняются по команде  Заполнить – Поддержание запаса.

Задать параметры поддержания запаса можно одновременно для нескольких выделенных позиций.

Если товар уже есть в списке настроек поддержании запасов с заданными значениями параметров поддержания запасов, то при добавлении такого товара с помощью стандартной обработки подбора товаров, с использованием механизма отбора товаров или путем загрузки из внешнего файла, ранее настроенные параметры поддержания запасов (минимальный, максимальный запасы) не обнуляются. Например, в настройках поддержания запасов добавлен товар, для которого заданы значениями минимального запаса (100) и максимального запаса (200), то при добавлении этой позиции (например, путем загрузки из внешнего файла со значениями минимального запаса = 0 и максимального запаса = 0), значения минимального и максимального запасов остаются прежними.

Для номенклатуры, у которой включен учет по характеристикам, в форме настройки поддержания запасов показывается настройка «общая для всех характеристик». Это позволяет задать индивидуальные параметры поддержания запасов для характеристики номенклатуры (команда Группировка – Установить индивидуальные параметры для характеристик).

Для удаления товаров из списка поддерживаемых запасов предназначена команда Исключить из поддерживаемых запасов. При удалении товара, для которого также настроены общие параметры поддержания запаса для номенклатуры в целом, товар не исчезнет из списка, а станет неактивным.

В рабочем месте по настройке поддержания запасов предусмотрено объединение номенклатурных позиций в произвольные группировки поддерживаемых запасов (например, объединение номенклатуры по стабильности продаж, товарообороту, уровню спроса, объему продаж и др.) – команда Группировка – Сгруппировать. Использование группировки упрощает работу по настройке параметров поддержания запасов и позволяет для большого количества номенклатуры задать общие параметры подержания запасов. Наименование группы вводится в произвольной форме. Параметры поддержания запасов, заданные для группы, будут действовать в отношении всех позиций номенклатуры на различных складах, входящих в данную группировку.

Понятие группировки не имеет отношение к складу. Группировка параметров поддержания запаса - это группировка одинаковых настроек параметров поддержания запаса, для любого состава номенклатуры и любого состава складов, без ограничений.

Например, есть снабженец, которому необходимо управлять поддержанием запаса для 10 000 позиций, исходя из спроса, объема средств.

Назначать параметры поддержания запасов (например, мин – макс) на каждую отдельную позицию из 10 000, а затем актуализировать по причине изменения объема вкладываемых в запасы средств, трудоемко.

Как средство упрощения снабженец ранжирует весь этот список позиций, исходя из особенностей спроса на номенклатурные позиции, получает 20-100 устойчивых групп, путем группировки параметров c примерными наименованиями:

■ Ходовые позиции, вкладываем 40% средств.

■ Средний спрос №1, вкладываем 5% средств.

■ Средний спрос №n, вкладываем 5% средств.

■ Нестабильное потребление, под заказ.

Далее из рабочего места по настройке поддержания запасов снабженец назначает для полученных группировок параметры поддержания запасов, которые будут действовать на различных складах, и образует содержимое этих группировок, добавляя в них позиции из общего списка (из 10 000 позиций):

■ «Ходовые позиции, вкладываем 40% средств»:

○ Товар 1 + Склад 1.

○ Товар 1 + Склад 2.

○ Товар 2 + Склад 1.

○ Товар 2 + Склад 2.

В строках группировок склад не заполнен, как и номенклатура. Группировка отображается, если в ней есть хотя бы одна строка, удовлетворяющая отбору по складу.

Перенос номенклатурных позиций из одной группы поддерживаемых запасов в другую выполняется по команде Группировка – Перенести в группу.

Исключение номенклатурных позиций из группировки поддерживаемых запасов доступно по команде Группировка – Исключить из группы.

## Расчет среднедневного потребления товаров (расчет по статистике)

Расчет среднедневного потребления выполняется в соответствии с заданными настройками расчета среднедневного потребления по статистике прошлых периодов.

Настройки параметров расчета среднедневного потребления по статистике выполняются в форме Настройка параметров расчета среднедневного потребления (доступна по команде Еще – Настройка расчета статистики потребления в рабочем месте Настройка поддержания запасов).

Также доступ к настройкам параметров расчета среднедневного потребления обеспечивается по соответствующей гиперссылке на форме обработки Формирование заказов по потребностям (на шаге 1, Отбор потребностей).

При расчете среднедневного потребления есть возможность задать настройку учета сезонных колебаний:

■ Не учитывать – сезонные колебания не учитываются.

■ По сезонным коэффициентам – среднедневное потребление рассчитывается по данным за указанный период (в поле Количество периодов):

○ Если товар не принадлежит товарной категории, то берется статистика потребления товара за периоды, указанные в настройке. Например, если указано за 12 месяцев, то берутся 12 месяцев, предшествующие текущему.

○ Если товар принадлежит товарной категории, то независимо от того, сколько месяцев указано в настройках, берется потребление товара за год назад месяц (или год или любая другая периодичность, которая указана в настройках) и умножается на поправочный (сезонный) коэффициент. Для расчета коэффициента берутся все товары данной товарной категории. Статистика рассчитывается за период указанный в настройках (например, за предыдущие 12 месяцев). Далее статистика рассчитывается еще раз, только уже со смещением ровно на год (например, это будет период от двух лет назад до года назад). Полученные два значения делятся друг на друга, тем самым получаем поправочный коэффициент динамики по товарной категории.

■ По аналогичному периоду прошлого года – среднедневное потребление рассчитывается по данным за период (аналогичный текущему месяцу прошлого года). Среднедневное потребление корректируется согласно динамике потребления соответствующей товарной категории. Динамика потребления по товарной группе формируется по данным за указанный период и за аналогичный период относительно прошлого года.

При расчете среднедневного потребления учитываются все расходы со склада за минусом возвратов (возврат товаров от клиента, возвратные перемещения, возврат из производства и т.д.). Для розничных складов перемещения товаров в расчет не включаются.

В расчете среднедневного потребления участвуют следующие документы:

■ Внутреннее потребление товаров;

■ Корректировка реализации;

■ Ордер на отражение недостач товаров;

■ Ордер на отражение порчи товаров;

■ Передача сырья переработчику;

■ Списание недостач товаров;

■ Порча товаров;

■ Пересортица товаров;

■ Расходный ордер на товары;

■ Реализация товаров и услуг;

■ Сборка товаров;

■ Отчет о розничных продажах;

■ Чек ККМ.

■ Передача давальцу.

Продажи за период уменьшаются документами:

■ Возврат сырья от переработчика;

■ Возврат товаров от клиента;

■ Чек ККМ на возврат.

Расчет среднедневного потребления выполняется двумя методами.

**1-й метод** – не учитывает дни «неполных продаж». Если в начале дня не было остатка или в конце дня не было остатка (товар закончился), то расход этого дня не учитывается в статистике. Расчет среднедневного потребления товаров выполняется без учета нулевых остатков на начало или конец дня.

При расчете соблюдаются следующие условия, на рабочую дату:

■ В наличии начальный остаток > 0 (на начало дня).

■ В наличии конечный остаток > 0 (на конец дня).

Если были остатки на начало и конец дня, то такой день учитываются в статистике независимо от того, был расход со склада в этот день или нет.

Среднедвневное потребление = Количество расхода за период (берется количество расхода в даты, на которые есть остатки на начало и конец дня)/Количество рабочих дней склада с ненулевыми остатками в течение дня (на начало и конец дня).

**2-й метод** – учитывает все расходы периода, в том числе и в дни «неполных продаж». Если в начале дня не было остатка или в конце дня не было остатка (товар закончился), то расход этого дня учитывается в статистике.

Если были остатки на начало и конец дня, то такой день учитываются в статистике независимо от того, был расход со склада в этот день или нет.

Период отсчитывается от вчерашнего дня – назад. Количество рабочих дней рассчитывается в соответствии с календарем склада. Если календарь склада не задан, то используется календарь предприятия, в противном случае все дни периода считаются рабочими.

В качестве окончательного значения среднедневного потребления берется максимальное значение, рассчитанное с учетом и без учета дней «неполных продаж».

Расчет среднедневного потребления выполняется регламентным заданием. Если регламентное задание отключено, то расчет будет выполняться фоновым заданием при задании отбора по складу в рабочем месте по настройке поддержания запасов.

Среднедневное потребление рассчитывается «налету» и в обработке «Формирование заказов по потребностям», в момент, когда обработка рассчитывает рекомендуемое количество к заказу по номенклатуре с установленным методом обеспечения «Расчет по статистике». Рассчитанное среднедневное потребление отображается справочно в форме «Параметры обеспечения потребностей».

При расширенном варианте обеспечения потребностей максимальное значение среднедневного потребления товаров отображается в параметрах обеспечения потребностей, доступных по гиперссылке метода обеспечения «Расчет по статистике» в рабочем месте Формирование заказов по потребностям на шаге 3, и в рабочем месте по настройке поддержания запасов на закладке «Рекомендации по изменению».

Значение в скобках (+/- 5,805) – это среднеквадратичное отклонение. Квадратичное отклонение считается из тех же данных по формулам математической статистики: корень квадратный из выборочной дисперсии (несмещенной оценки дисперсии).

На основании статистики среднедневного потребления автоматически рассчитываются значения максимального и минимального запасов для номенклатуры. Величина минимального запаса рассчитывается на срок исполнения заказа, величина максимального запаса – на обеспечиваемый период.

Пример расчета потребления по статистике удаленных складов, источником обеспечения которых является распределительный центр, представлен на схеме. Норма потребления розничных точек рассчитывается как продажи розничных точек умножить на коэффициент рабочих дней склада.

Пример расчета потребления по статистике, как с учетом, так и без учета сезонных коэффициентов представлен на схеме.

### Пример расчета среднедневного потребления

Исходные данные:

■ Заданы настройки поддержания запасов для номенклатуры.

■ Заданы настройки параметров расчета среднедневного потребления, при которых период, за который выполняется расчет среднедневного потребления, – с 01.03.24 по 30.04.24.

■ Количество рабочих дней склада в периоде с 01.03.24 по 30.04.24, за который выполняется расчет статистики среднедневного потребления, – 41.

■ Расход со склада за период с 01.03.24 по 30.04.24 г. – 33 ед.

Расчет среднедневного потребления товаров выполняется одновременно двумя методами.

**1-й метод**. Расчет среднедневного потребления товаров за вычетом «неполных» дней продаж.

К расчету принимается только расход:

■ в рабочий день;

■ в этот рабочий день ненулевой начальный и конечный остаток.

В данном примере учитываются все расходы за минусом возврата товаров от клиента 2 ед., перемещения товара 8 ед. на 26.03 и реализации товара 1 ед. на 29.03.

Расход со склада = 33–8-1–2 = 22 ед.

К расчету принимаются только дни:

■ этот день рабочий;

■ в этот рабочий день ненулевой начальный и конечный остаток.

В периоде для расчета статистики с 01.03.24 по 30.04.2024 количество рабочих дней склада 41, из которых даты 27.03, 28.03 исключаются, поскольку в эти даты не было остатков совсем (ни начального остатка, ни конечного остатка), также исключаются даты 26.03 (т.к на дату конечный остаток = 0) и 29.03 (т.к на дату начальный остаток = 0).

Среднедневное потребление = Расход со склада (берется количество расхода в даты, на которые есть остатки на начало и конец дня)/Количество рабочих дней склада с ненулевыми остатками в течение дня (на начало и конец дня).

Среднедневное потребление = Расход со склада/Количество рабочих дней склада в периоде = (2+1+1+3+5+12-2 ед. возврат товаров от клиента)/(41 рабочий день в периоде - 4 рабочих даты 26.03, 27.03, 28.03, 29.03 в периоде) = 22/37 = 0,595 шт

**2-й метод**. Расчет среднедневного потребления с учетом «неполных» дней продаж.

При расчете среднедневного потребления товаров учитываются даты, на которые имеются нулевые остатки на начало или конец дня, и расход в эти даты.

К расчету принимается расход:

■ в рабочий день;

■ в этот день ненулевой начальный и/или конечный остаток.

В данном примере учитываются все расходы только за минусом возврата товаров от клиента 2 ед.

Расход со склада = 33–2 = 31 ед.

К расчету принимаются только дни:

■ этот день рабочий;

■ в этот рабочий день ненулевой начальный и/или конечный остаток.

В периоде для расчета статистики с 01.03.24 по 30.04.2024 количество рабочих дней склада 41, из которых даты 27.03, 28.03 исключаются, поскольку в эти даты не было остатков совсем (ни начального остатка, ни конечного остатка).

Среднедневное потребление товаров рассчитывается как: Расход со склада/Количество рабочих дней склада в периоде = (2+1+1+8+1+3+5 +12 -2 ед. возврат товаров от клиента)= (33-2)/(41 рабочий день в периоде - 2 рабочих даты 27.03, 28.03 в периоде) = 31/39 = 0,795 шт

В качестве окончательного значения среднедневного потребления берется максимальное значение, полученное при помощи двух методов расчета среднедневного потребления.

Максимальное значение среднедневного потребления товаров 0,795 (+/- 2,412) шт (статистика за 01.03.2024 – 30.04.2024) отображается в параметрах обеспечения потребностей, доступных по гиперссылке «Расчет по статистике» в рабочем месте «Формирование заказов по потребностям» на шаге 3.

Также максимальное значение среднедневного потребления товаров отображается в рабочем месте «Настройка поддержания запасов» на закладке «Рекомендации по изменению» в колонке «Среднедневное потребление».

Среднеквадратичное отклонение рассчитывается по формуле = √ (Σ (x – μ)² /(N-1)), где:

■ x - значение расхода на рабочую дату склада. Если на рабочую дату склада нулевое значение расхода, то при расчете  учитывается это нулевое значение.

■ μ - среднедневное потребление, рассчитанное по статистике (берется максимальное значение, полученное при помощи двух методов расчета по статистике).

■ N - количество значений в выборке, это количество рабочих дней склада в периоде, используемых для расчета среднедневного потребления.

Для расчета среднеквадратичного отклонения используются данные (значение расхода, среднедневное потребление и количество рабочих дней склада), при которых рассчитано максимальное значение среднедневного потребления.

Максимальное значение среднедневного потребления = 0,795 ед.

Количество рабочих дней склада = 39, соответственно N = 39 значений и при вычислении дисперсии делим на N-1, т.е не на 39 рабочих дней, а на 38.

При расчете дисперсии учитывается и нулевое количество расхода на рабочую дату склада.

Дисперсия = Σ ((2 значение расхода со склада на рабочий день – 0,795)² + (1 - 0,795)² + (1 - 0,795)²+ (8 - 0,795)² + (1 - 0,795)²) + (3 - 0,795)² + (5 - 0,795)² + (12 - 0,795)² + (31 рабочий день склада с нулевым значением расхода в периоде \* (0 - 0,795)²)/(39-1) = (1,4521 + 0,0421 + 0,0421 + 51,9121 + 0,0421 + 4,8621 +17,6821 + 125,5521 + 19,5951)/(39 -1) = 5,8206

Среднеквадратичное отклонение = √5,8208 = 2,412

В рабочем месте «Настройка поддержания запасов» на закладке «Рекомендации по изменению» в колонке Отклонение потребления, % отображается значение, рассчитанное как Среднедневное потребление/Среднеквадратичное отклонение.

## Метод обеспечения «Заказ под заказ»

Если требуется обеспечивать потребности номенклатуры по заказам на отгрузку, то для этих целей предусмотрен метод обеспечения потребностей Заказ под заказ.

Обеспечение товаров под заказ характеризуется наименьшей потребностью в оборотных средствах и низкой вероятностью возникновения избыточных запасов.

Использование метода Заказ под заказ позволяет:

■ обеспечивать только количество товаров, необходимое для закрытия заказов по потребностям;

■ формировать заказы (заказы поставщику, заказы на перемещение и т. д.) на обеспечение заказов на отгрузку.

При этом методе не задаются параметры поддержания запаса.

Метод обеспечения Заказ под заказ присваивается по умолчанию при условии, что товар не добавлен в настройки поддержания запасов. Отдельная возможность установки этого метода не предусмотрена.

## Режимы работы распределительного центра

Для распределительного центра доступны режимы работы НСИ и администрирование – Настройка НСИ и разделов – Склад и доставка – Обеспечение потребностей, при которых:

■ Обеспечиваются потребности, зафиксированные только на самом распределительном центре (режим Планируемые отгрузки со склада на удаленные склады). При данном режиме учитываются операции:

○ Продажи, сборка/разборка, передача в производство, прочие списания с распределительного центра.

○ Перемещение с распределительного центра на удаленные склады, связанные с этим распределительным центром согласно схемам обеспечения.

○ Перемещение с распределительного центра на склады, не связанные с этим распределительным центром согласно схемам обеспечения.

■ Обеспечиваются потребности, зафиксированные как на самом распределительном центре, так и на складах, для которых распределительный центр является источником обеспечения Планируемые отгрузки с удаленных складов. При данном режиме учитываются операции:

○ Продажи, сборка/разборка, передача в производство, прочие списания с распределительного центра

○ Продажи, сборка/разборка, передача в производство, прочие списания с удаленных складов, связанных с распределительным центром согласно схемам обеспечения

○ Перемещение с распределительного центра и с его удаленных складов на склады, не связанные с данным распределительным центром согласно схемам обеспечения.

### «Планируемые отгрузки со склада на удаленные склады»

Если необходимо обеспечивать потребности в номенклатуре, зафиксированные только на самом распределительном центре (например, путем формирования заказов поставщикам, заказов на перемещение), то рекомендуется использовать режим Планируемые отгрузки со склада на удаленные склады.

Пример. Для товара «539047001 Фильтроэлемент» заданы параметры поддержания запасов на распределительном центре «Центральный склад\_1».

На распределительном центре «Центральный склад\_1» товар «539047001 Фильтроэлемент» обеспечивается путем закупки у поставщика. Для распределительного центра задан способ обеспечения потребностей с типом обеспечения «Покупка».

На удаленном складе «Склад отгрузки» товар «539047001 Фильтроэлемент» обеспечивается путем перемещения с распределительного центра в соответствии со способом обеспечения потребностей. Для удаленного склада «Склад отгрузки» задан способ обеспечения потребностей с типом обеспечения «Перемещение» и источник обеспечения - распределительный центр «Центральный склад\_1».

В рабочем месте по формированию заказов по потребностям для распределительного центра учитываются только остатки на самом распределительном центре (шаг 3 Поддержание запасов).

Если зафиксирована потребность заказом на отгрузку с удаленного склада «Склад отгрузки», источником обеспечения которого является распределительный центр «Центральный склад\_1»,

в рабочем месте по формированию заказов по потребностям на шаге 4 Обеспечение заказов к отгрузке) учитываются только потребности на удаленном складе и потребности по заказу на отгрузку показываются в одну строки: на обеспечение удаленного склада «Склад отгрузки».

Будет формироваться заказ на перемещение с распределительного центра «Центральный склад\_1» на удаленный склад «Склад отгрузки».

### «Планируемые отгрузки с удаленных складов»

Если необходимо обеспечивать потребности в номенклатуре, зафиксированные как на распределительном центре, так и на удаленных складах, для которых распределительный центр является источником обеспечения, учитывать остатки и потребности всех складов, питающихся из этого распределительного центра, то рекомендуется использовать режим Планируемые отгрузки с удаленных складов.

Пример. Для товара «Фильтроэлемент» заданы параметры поддержания запасов на распределительном центре «Центральный склад».

На распределительном центре «Центральный склад» товар «Фильтроэлемент» обеспечивается путем закупки у поставщика. Для распределительного центра задан способ обеспечения потребностей с типом обеспечения «Покупка».

На удаленном складе «Склад отгрузки» товар «Фильтроэлемент» обеспечивается путем перемещения с распределительного центра в соответствии со способом обеспечения потребностей. Для удаленного склада «Склад отгрузки» задан способ обеспечения потребностей с типом обеспечения «Перемещение» и источник обеспечения - распределительный центр «Центральный склад».

В рабочем месте по формированию заказов по потребностям на шаге 3 Поддержание запасов для распределительного центра («Центральный склад») остаток (колонка Остаток) и ожидаемые поступления по заказам (колонка Заказы к поступлению) отображаются с учетом остатков и ожидаемых поступлений по заказам на удаленных складах, обеспечиваемых этим распределительным центром, за исключением ожидаемых перемещений по заказам между распределительным центром и удаленными складами.

Чтобы программа на шаге 3 для поддержания запасов рекомендовала «К заказу» как на распределительном центре, который является источником обеспечения удаленного склада, так и «К заказу» на удаленном складе перемещением из распределительного центра, то необходимо настроить параметры поддержания запасов как на распределительном центре, так и на удаленном складе.

Если зафиксирована потребность заказом на отгрузку только на удаленном сладе «Склад отгрузки», источником обеспечения которого является распределительный центр «Центральный склад»,

на шаге 4 Обеспечение заказов к отгрузке потребность по заказу на отгрузку с удаленного склада будет показываться в две строки:

■ к заказу на обеспечение распределительного центра, который является источником обеспечения удаленного склада. Будет формироваться заказ на поставку в распределительный центр;

■ к заказу на обеспечение удаленного склада. Будет формироваться заказ на перемещение из распределительного центра на удаленный склад.

Дата отгрузки для обеспечения потребностей на распределительном центре уменьшается от исходной даты отгрузки по обеспечению потребностей на удаленном складе на длительность перемещения. Длительность перемещения задается в способе обеспечения потребностей с типом обеспечения «Перемещение».

Чтобы при помощи рабочего места по формированию заказов по потребностям сформировать заказ на поставку в распределительный центр и заказ на перемещение из распределительного центра на удаленный склад, то в обработке Формирование заказов по потребностям на шаге 1 необходимо указать:

■ склад, являющийся источником обеспечения удаленных складов (распределительный центр).

■ склад, обеспечиваемый за счет распределительного центра.

Если склад является удаленным складом одной распределительной сети и одновременно распределительным центром другой распределительной сети, то для него в рабочем месте Формирование заказов по потребностям отображаются только отгрузки со складов этого распределительного центра наружу, а внутренние перемещения с распределительного центра на удаленные склады не отображаются. Например, оформлен «Заказ материалов в производство», в котором указан склад-отправитель материалов (например «Центральный склад»), на котором создается потребность. Этот склад-отправитель является удаленным складом и одновременно распределительным центром. Если нужно обеспечивать этот склад («Центральный склад») путем формирования заказа на перемещение со склада-отправителя на склад-получателя («Центральный склад»), необходимо включить настройку  «Планируемые отгрузки со склада на удаленные склады».

#### Поддержка каскада перемещений в рабочем месте «Формирование заказов по потребностям»

Предусмотрен способ расчета потребностей для центра распределительных сетей с учетом потребностей всех подчиненных складов сети:

■ Настройка НСИ и Администрирование – Склад и доставка – Для распределительного центра обеспечению подлежат: Планируемые отгрузки с удаленных складов.

■ Подчинение склада задавалось настройкой способа обеспечения с типом «Перемещение».

■ Подчиненными складами считались только склады, непосредственно связанные перемещением.

■ Если склады 1 и 3 связаны цепочкой перемещений 1 – 2 – 3, то потребности склада 3 не учитывались для расчета общей потребности склада 1.

Также поддержан расчет потребностей центра сети, с произвольным количеством вложенности.

Расчет используется в рабочем месте Формирование заказов по потребностям в задачах:

■ Получение суммарных запасов распределительного центра на шаге поддержания запасов.

■ Получение потребностей распределительного центра по заказам, включая заказы, оформленные непосредственно на распределительный центр и на все его подчиненные склады.

■ Получение суммарных запасов (фактических и ожидаемых к поступлению) на складах сети с учетом запасов на подчиненных складах для задачи расчета обеспеченности потребностей по заказам распределительного центра.

■ Исключение заказов на перемещение внутри сети из расчета потребностей центра и запасов в ожидаемых поступлениях.

Ограничение: зацикливание перемещений пока решается только технически, остановкой расчета дальнейшей вложенности.

В рабочем месте Формирование заказов по потребностям потребность по заказу клиента проброшена со склада «Торговая точка» на склад закупки «РЦ большой» транзитом через буферный склад «РЦ маленький».
