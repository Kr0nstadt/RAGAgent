# Herdr / Pi workspace для моделирования 1С ERP

Workspace превращает файл ТЗ в отдельный сохраняемый Task Graph, проводит несколько раундов уточнений, строит цепи объектов ERP и сохраняет проверенную инструкцию.

## Быстрый запуск

Из корня проекта:

```powershell
.\start_erp_pi.ps1
```

В открывшемся Pi напишите обычной фразой:

```text
Реализуй ТЗ из файла C:\путь\к\техническое_задание.docx
```

или используйте slash-команду:

```text
/erp-task C:\путь\к\техническое_задание.docx
```

Координатор создаст Task Graph, покажет первый раунд максимум из 10 вопросов и будет сохранять ответы. Следующие раунды адаптируются к предыдущим ответам. После уточнений он вызовет проектных субагентов, подготовит и проверит инструкцию.

Финальный файл появляется здесь:

```text
task_data/<task-id>/final_instruction.md
```

## Субагенты

- `erp-translator` — перевод требований на подтверждённые объекты ERP.
- `question-auditor` — ищет пробелы и приоритизирует новые уточнения.
- `erp-process-planner` — строит обратные зависимости НСИ, сквозную цепь документов, регистров и регистраторов.
- `instruction-writer` — пишет подробную пошаговую инструкцию.
- `instruction-verifier` — независимо проверяет точные ERP-утверждения по графу.

Координатор остаётся единственным собеседником пользователя. Изолированные субагенты обмениваются результатами через файлы задачи.

## Состояние и восстановление

Workflow хранится в `task_data/<task-id>/workspace_state.json`:

```text
INGESTED -> NEEDS_CLARIFICATION -> READY_TO_PLAN -> PLANNED -> COMPLETE
```

Повторная подача того же файла определяется по SHA-256 и продолжает существующий Task Graph. Статический четырёхслойный граф ERP для новой задачи пересобирать не нужно.

Локальные команды диагностики:

```powershell
python workspace_task.py status <task-id>
python workspace_task.py prepare <task-id> --limit 10
python workspace_task.py context <task-id>
```

## Безопасность LLM

`WORMSOFT_API_KEY` остаётся в `.env`. Стартовый скрипт передаёт его только процессу Pi и не печатает в терминал. Графовые команды `instruct` и `interactive` не включаются: все их локальные операции выполняются без API, а вызов Wormsoft контролирует Pi.
